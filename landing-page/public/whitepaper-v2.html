Abstract

The emergence of Mixture-of-Experts (MoE) architectures has fundamentally transformed large-scale neural network design, enabling unprecedented model capacity while maintaining computational tractability through sparse activation patterns. However, contemporary MoE implementations universally employ a fixed top-k routing strategy that treats all input tokens with identical computational budgets, irrespective of the inherent complexity or ambiguity of individual routing decisions.

This paper presents Adaptive-K routing, a principled methodology for dynamic expert selection that leverages Shannon entropy of the routing distribution as a proxy for token-level uncertainty. We provide theoretical foundations grounded in information theory and rate-distortion theory, comprehensive empirical validation across three production-scale MoE architectures (Mixtral 8×7B achieving 52.5% compute reduction, Qwen1.5-MoE 32.4%, and OLMoE-1B-7B 24.7%), and production-ready integration with NVIDIA TensorRT-LLM (PR #10672). We further present the ROI Calculator methodology for enterprise cost estimation and outline a strategic roadmap for industry adoption targeting hyperscale AI infrastructure providers.

Keywords: Mixture-of-Experts, Sparse Models, Dynamic Routing, Information Theory, TensorRT-LLM, Computational Efficiency, Large Language Models, Enterprise AI, DeepSeek-V3

Theoretical Foundations

3.1 Mixture-of-Experts Formalism

A Mixture-of-Experts layer consists of \(N\) expert networks \(\{E_1, \ldots, E_N\}\) and a gating (router) network \(G\). For input token \(x \in \mathbb{R}^d\), the output is:

$$y = \sum_{i \in \mathcal{T}_K(x)} w_i(x) \cdot E_i(x)$$ (1)

where \(\mathcal{T}_K(x)\) denotes the top-K experts selected by the router, and \(w_i(x)\) are the normalized routing weights.

3.2 Router Probability Distribution

The router produces logits \(g(x) = W_g \cdot x\) that are converted to a probability distribution:

$$p_i(x) = \frac{\exp(g_i(x) / \tau)}{\sum_{j=1}^{N} \exp(g_j(x) / \tau)}$$ (2)

where \(\tau\) is an optional temperature parameter.

3.3 Shannon Entropy as Routing Confidence

Definition 3.1 (Routing Entropy)

The Shannon entropy of the routing distribution quantifies the router's uncertainty:

$$H(x) = -\sum_{i=1}^{N} p_i(x) \log p_i(x)$$ (3)

Bounds: \(0 \leq H(x) \leq \log N\), with \(H(x) = 0\) iff deterministic routing, and \(H(x) = \log N\) iff uniform distribution.

3.4 Information-Theoretic Justification

Proposition 3.1 (Entropy-Complexity Relationship)

Let \(p(x)\) be the routing distribution and \(C(x)\) be the "routing complexity"—the minimum number of experts needed to capture \(\alpha\)-fraction of the routing probability mass. Then:

$$C_\alpha(x) \leq \frac{H(x)}{\log(1/\alpha)} + 1$$

This establishes that low entropy implies low routing complexity, justifying the use of fewer experts.

3.5 Rate-Distortion Framework

We formalize Adaptive-K as a rate-distortion optimization problem. Define:

  • Rate \(R\): Average number of experts activated (computational cost)
  • Distortion \(D\): Quality degradation from reduced K
$$D_K(x) = \|y_K(x) - y_{\text{full}}(x)\|_2^2$$ (4)

The optimal K selection minimizes expected cost subject to quality constraint:

$$K^*(x) = \arg\min_K \{K : \mathbb{E}[D_K(x)] \leq \epsilon\}$$ (5)
Proposition 3.2 (Entropy-Distortion Bound)

For tokens with routing entropy \(H(x) < H^*\), there exists \(K < K_{\max}\) such that \(\mathbb{E}[D_K(x)] < \epsilon\). The threshold \(H^*\) depends on expert diversity and can be empirically calibrated.

Adaptive-K Routing Algorithm

4.1 Algorithm Specification

Algorithm 1: Adaptive-K Routing
Input: Router logits g(x) ∈ ℝᴺ K values 𝒦 = {k₁ < k₂ < ... < kₘ} Entropy thresholds Θ = {θ₁ < θ₂ < ... < θₘ₋₁} Output: Expert indices I, weights W, selected K // Phase 1: Compute routing distribution 1. p ← softmax(g) // ℝᴺ probability vector // Phase 2: Compute entropy 2. H ← −∑ᵢ pᵢ log(pᵢ + ε) // Shannon entropy, O(N) // Phase 3: Select K via threshold lookup 3. K ← kₘ // Default to max 4. for j = m-1 down to 1 do 5. if H < θⱼ then K ← kⱼ // Phase 4: Execute top-K routing 6. I, W_raw ← TopK(p, K) // Standard top-K 7. W ← W_raw / sum(W_raw) // Renormalize 8. return I, W, K

Complexity: O(N) for entropy computation + O(N log K) for top-K selection. The entropy overhead is negligible compared to expert forward pass cost O(Kd²).

4.3 Batched Inference Implementation

For efficient GPU execution with variable K per token, we use masked batching: 

def adaptive_k_batched(router_logits, thresholds, k_values):
    # router_logits: [batch, num_experts]
    probs = F.softmax(router_logits, dim=-1)
    entropy = -(probs * torch.log(probs + 1e-9)).sum(dim=-1)
    
    # Vectorized K selection
    k_per_token = torch.full_like(entropy, k_values[-1], dtype=torch.long)
    for i, threshold in enumerate(thresholds):
        k_per_token = torch.where(entropy < threshold, k_values[i], k_per_token)
    
    # Compute top-K_max, then mask
    k_max = max(k_values)
    topk_probs, topk_indices = torch.topk(probs, k_max, dim=-1)
    
    # Create validity mask: [batch, k_max]
    positions = torch.arange(k_max, device=probs.device)
    mask = positions.unsqueeze(0) < k_per_token.unsqueeze(1)
    
    # Zero invalid positions and renormalize
    masked_probs = topk_probs * mask.float()
    weights = masked_probs / (masked_probs.sum(dim=-1, keepdim=True) + 1e-9)
    
    return topk_indices, weights, k_per_token

class AdaptiveKMoeRoutingMethod(nn.Module):
    """
    Entropy-based Adaptive-K routing for TensorRT-LLM MoE.
    
    Compatible with BaseMoeRoutingMethod interface.
    Drop-in replacement for existing top-k routing.
    """
    
    def __init__(self, k_min=2, k_max=8, entropy_thresholds=None):
        self.config = AdaptiveKConfig(
            k_min=k_min,
            k_max=k_max,
            entropy_thresholds=entropy_thresholds or [1.3, 1.7]
        )
    
    def apply(self, router_logits) -> Tuple[Tensor, Tensor]:
        """Same interface as standard routing methods."""
        probs = F.softmax(router_logits, dim=-1)
        entropy = self.compute_entropy(probs)
        k_per_token = self.select_k_per_token(entropy)
        
        # Returns (expert_indices, weights) - compatible interface
        return self._route_with_variable_k(probs, k_per_token)
    
    def get_stats(self) -> dict:
        """Runtime statistics for monitoring."""
        return {
            "k_distribution": self._k_counts,
            "mean_entropy": self._entropy_sum / self._total_tokens,
            "compute_savings_pct": self._compute_savings()
        }

7.3 Calculation Formula

function calculateROI(dailyTokensM, pricePerM, savingsRate) {
    // Monthly calculations (30 days)
    const monthlyTokens = dailyTokensM * 30;
    const baselineCost = monthlyTokens * pricePerM;
    const adaptiveCost = baselineCost * (1 - savingsRate / 100);
    const monthlySavings = baselineCost - adaptiveCost;
    const annualSavings = monthlySavings * 12;
    
    return {
        baselineCost,     // Monthly baseline
        adaptiveCost,     // Monthly with Adaptive-K
        monthlySavings,   // Monthly savings
        annualSavings     // Annual projection
    };
}

8.3 Future Research Directions

Research Objective: Per-Layer Adaptive Thresholds

Our layer-wise analysis reveals that entropy distributions vary significantly across MoE layers. Future work will develop per-layer threshold calibration for optimized savings:

  • Early layers: Higher entropy → More conservative thresholds
  • Middle layers: Lower entropy → More aggressive thresholds
  • Late layers: Variable → Learned thresholds

Expected improvement: Additional 5-10% savings.

8.4 Theoretical Extensions

8.4.1 Learned Thresholds

End-to-end learning of entropy thresholds via straight-through gradient estimators:

$$\theta^* = \arg\min_\theta \mathcal{L}_{\text{task}} + \lambda \cdot \mathbb{E}[K(x; \theta)]$$ (9)

8.4.2 Entropy-Aware Training

Training MoE models with explicit entropy regularization to enhance Adaptive-K compatibility:

$$\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{task}} + \alpha \cdot \text{Var}(H(x)) - \beta \cdot \mathbb{E}[H(x)]$$ (10)

This encourages diverse entropy distributions (high variance) with overall low mean entropy.

8.4.3 Multi-Modal Extension

Investigation of Adaptive-K for vision-language MoE models (e.g., MoE-LLaVA) where image tokens may exhibit different entropy characteristics than text tokens.

"""
AdaptiveKMoeRoutingMethod for TensorRT-LLM
File: tensorrt_llm/_torch/modules/fused_moe/routing.py
"""

import torch
import torch.nn.functional as F
from torch import nn
from typing import Tuple, List, Optional
from dataclasses import dataclass


@dataclass
class AdaptiveKConfig:
    """Configuration for Adaptive-K routing."""
    k_min: int = 2
    k_max: int = 8
    k_values: List[int] = None
    entropy_thresholds: List[float] = None
    
    def __post_init__(self):
        if self.k_values is None:
            self.k_values = [self.k_min, 
                           (self.k_min + self.k_max) // 2, 
                           self.k_max]
        if self.entropy_thresholds is None:
            self.entropy_thresholds = [1.3, 1.7]


class AdaptiveKMoeRoutingMethod(nn.Module):
    """Entropy-based Adaptive-K routing for MoE models."""
    
    def __init__(self, config=None, k_min=2, k_max=8,
                 entropy_thresholds=None):
        super().__init__()
        if config:
            self.config = config
        else:
            self.config = AdaptiveKConfig(
                k_min=k_min, k_max=k_max,
                entropy_thresholds=entropy_thresholds or [1.3, 1.7]
            )
        self.k_max = self.config.k_max
        self._reset_stats()
    
    def compute_entropy(self, probs):
        return -torch.sum(probs * torch.log(probs + 1e-9), dim=-1)
    
    def select_k_per_token(self, entropy):
        k = torch.full_like(entropy, self.config.k_values[-1], 
                          dtype=torch.int32)
        for i, thresh in enumerate(self.config.entropy_thresholds):
            k = torch.where(entropy < thresh, 
                          self.config.k_values[i], k)
        return k
    
    def apply(self, router_logits) -> Tuple[torch.Tensor, torch.Tensor]:
        probs = F.softmax(router_logits, dim=-1)
        entropy = self.compute_entropy(probs)
        k_per_token = self.select_k_per_token(entropy)
        
        topk_vals, topk_idx = torch.topk(probs, self.k_max, dim=-1)
        
        # Mask based on per-token K
        k_range = torch.arange(self.k_max, device=probs.device)
        mask = k_range.unsqueeze(0) < k_per_token.unsqueeze(1)
        masked = torch.where(mask, topk_vals, torch.zeros_like(topk_vals))
        weights = masked / (masked.sum(dim=-1, keepdim=True) + 1e-9)
        
        self._update_stats(k_per_token, entropy)
        return topk_idx.to(torch.int32), weights
    
    def get_stats(self):
        if self._total == 0:
            return {}
        avg_k = sum(k * c / self._total for k, c in self._k_counts.items())
        return {
            "k_distribution": {k: c/self._total*100 
                              for k, c in self._k_counts.items()},
            "avg_k": avg_k,
            "compute_savings_pct": (1 - avg_k/self.k_max) * 100
        }

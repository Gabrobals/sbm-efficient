Adaptive-K Technical Whitepaper v1.0

Adaptive-K Routing for Mixture-of-Experts Language Models

Entropy-Based Dynamic Expert Selection for 25-52% Compute Savings

VertexData Research | January 2025 | Version 1.0
https://adaptive-k.vertexdata.it

Abstract: We present Adaptive-K, a dynamic routing mechanism for Mixture-of-Experts (MoE) language models that adjusts the number of activated experts per token based on router entropy. Unlike fixed top-K routing (e.g., K=8 in DeepSeek-V3), Adaptive-K activates fewer experts for simple tokens and more for complex ones. Validated on Mixtral 8x7B, OLMoE 1B-7B, and Qwen1.5-MoE-A2.7B, we demonstrate 25-52% compute savings with <0.5% accuracy degradation. The technique is production-ready via our open-source SDK and compatible with existing inference frameworks (vLLM, SGLang, TensorRT-LLM).

1. Introduction & Motivation

Enterprise AI infrastructure costs are experiencing unprecedented growth. According to a16z's 2024 enterprise survey, the average Fortune 500 company spent $7 million on LLM APIs and infrastructure, with 2-5x increases projected for 2025. SemiAnalysis estimates global AI datacenter power demand will reach 96 GW by 2026, representing a $20+ billion annual electricity cost.

Mixture-of-Experts (MoE) architectures have emerged as the dominant approach for scaling LLMs efficiently. DeepSeek-V3 (671B total, 37B activated), Mixtral 8x7B (46.7B total, 12.8B activated), and Qwen-MoE demonstrate that sparse activation can match dense model performance at significantly lower compute cost.

The Problem: All production MoE models use fixed top-K routing. DeepSeek-V3 activates exactly 8 experts per token regardless of token complexity. Simple tokens like "the" or punctuation receive the same compute budget as complex reasoning tokens.

We propose Adaptive-K routing: dynamically selecting K based on router confidence (entropy). This simple modification achieves substantial compute savings without retraining or architectural changes.

2. Background: MoE Architectures

2.1 Traditional MoE Routing

In a standard MoE layer, the router computes a probability distribution over N experts:

# Traditional top-K routing router_logits = router(hidden_states) # [batch, seq, num_experts] router_probs = softmax(router_logits, dim=-1) # Normalize to probabilities top_k_probs, top_k_indices = topk(router_probs, k=K) # Always select K experts

This fixed-K approach was established by Switch Transformers (K=1) and refined by GShard (K=2) and subsequent work. DeepSeekMoE introduced fine-grained experts (256 total, 8 activated) but maintained fixed routing.

2.2 The Entropy Signal

Router entropy measures the uncertainty in expert selection:

H(p) = -sum(p * log(p)) # Shannon entropy # Low entropy: Router is confident, few experts needed # High entropy: Router is uncertain, more experts beneficial
Entropy Level Interpretation Example Tokens Optimal K
H < 0.5 Very confident "the", ".", "," 1-2
0.5 ≤ H < 1.5 Moderate confidence Common words 2-4
1.5 ≤ H < 2.5 Some uncertainty Domain terms 4-6
H ≥ 2.5 High uncertainty Reasoning, code 6-8

3. Adaptive-K Methodology

3.1 Core Algorithm

def adaptive_k_routing(hidden_states, router, thresholds, k_values): """ Entropy-based adaptive expert selection. Args: hidden_states: [batch, seq, hidden_dim] router: Linear layer mapping to expert logits thresholds: List of entropy thresholds [t1, t2, ...] k_values: Corresponding K values [k1, k2, k3, ...] Returns: expert_indices: Selected expert indices per token expert_weights: Routing weights per expert """ logits = router(hidden_states) probs = softmax(logits, dim=-1) entropy = -sum(probs * log(probs + eps), dim=-1) # Select K based on entropy thresholds k_per_token = select_k_from_entropy(entropy, thresholds, k_values) # Dynamic top-k selection indices, weights = batched_topk(probs, k_per_token) return indices, weights

3.2 Per-Layer Adaptation

We observe that optimal K varies by layer position. Early layers (pattern matching) benefit from lower K, while later layers (reasoning/composition) require higher K. Our per-layer variant learns layer-specific thresholds:

8. Conclusion & Future Work

Adaptive-K routing demonstrates that significant compute savings (25-52%) are achievable in MoE inference without retraining or architectural changes. By leveraging the natural entropy signal from router distributions, we can dynamically allocate compute where it matters most.

Future Directions

  • Learned threshold optimization via reinforcement learning
  • Combination with MoE distillation techniques
  • Hardware-aware batching for variable K
